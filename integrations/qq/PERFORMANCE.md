# QQ 采集性能与测量

性能结果依赖本机消息规模、数据库变化量和系统负载。公开说明保留方法和实现边界，不发布维护者的账号规模、会话统计、源数据路径或逐轮活动记录。

## 页面复用

采集器按变化页构建下一代快照，避免每次完整重写明文主库。复用页面必须来自摘要和指纹均验证通过的可信上代；变化页继续使用页面认证与原有解密器。首次建立基线，或盐、密钥、配置变化及缓存损坏时，回到完整重建。

候选代先完成完整性检查、消息提取和入库，再原子发布。增量提取使用独立副本，保留当前代与上一代；失败或中断仍可使用上次可信数据。

## 测量方法

1. 使用 SQLite 一致备份准备同一冻结输入，准备成本不计入采集耗时。
2. 分别测量首次建基线、变化页刷新、重建进程后复用和源文件未变时的检查。
3. 记录各阶段耗时、系统记账的读写量、变化／复用页面数、CPU 与内存口径。
4. 在私有环境对照稳定消息 ID、会话、正文、发送者、时间和类型；公开报告只给匿名一致性结论。

macOS 进程记账、文件系统写回与 NAND 物理擦写不是同一指标，不据此承诺 SSD 寿命。前台与后台负载、初始化与稳态应分别记录；不能用少量静态输入推算全天消息量或固定每轮写入。

## 剩余成本

仍需检查源文件、认证变化页、扫描原生 ID 并规范化联系人等元数据。页面复用减少重复写入，并不承诺所有刷新都更快。无变化时跳过重建；失败重试可能增加实际成本。

采集等待和 ChatLab 拉取是独立设置，调低阅读端拉取频率不等于降低源库检查频率。部署时按 [接入指南](README.md) 配置，不使用维护者机器上的值作为产品默认。

## 回归范围

回归覆盖重启复用、消费者不能覆盖基线、提交失败与中断恢复、内容或指纹被篡改、源身份变化、活动 journal、可选库缺失、WAL 提交与清空、文件增长／缩容、零预分配、密钥和盐轮换、坏页面认证失败。测试使用临时数据；真实数据库、密钥与测量明细不进入仓库。
