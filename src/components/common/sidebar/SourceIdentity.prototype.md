# ChatLab 会话来源辨识设计

问题：QQ 与企业微信会话混排，只显示名称和消息量，无法在列表中辨认来源。

本版保留现有侧栏、品牌粉色和“全部／私聊／群聊”，新增来源筛选、列表平台标签和标题来源信息。`SourceIdentity.prototype.html` 是独立交互原型，使用示例记录，不连接用户数据库。

## 信息层次

| 位置 | 展示 | 解决的问题 |
| --- | --- | --- |
| 列表筛选区 | 全部来源／QQ／企微，附会话数 | 只看工作消息或 QQ 讨论；与私聊、群聊及名称搜索组合 |
| 每条会话第二行 | 图标 + 平台文字标签，后跟消息量 | 混排时直接辨认；标签不挤占群名，不依赖头像颜色 |
| 打开后的标题下方 | 平台／账号备注／会话类型／消息量 | 阅读前确认当前上下文，跨平台同名群仍可区分 |
| 来源详情 | 平台、账号备注、数据源、导入方式、同步间隔和时间 | 默认收起，确有需要时查看采集与导入信息 |

## 交互规则

- 来源筛选与类型筛选、搜索取交集。来源计数基于当前类型和搜索条件，选择平台后不会把其他平台的计数隐藏。
- 显式切换到另一平台时，若当前会话不属于该平台，打开筛选结果中的第一个会话；若没有结果则保留详情，空列表给出“清除筛选”。普通名称搜索和类型切换不强制跳转已打开会话。
- 同名会话按平台与稳定会话 ID 独立显示；不修改原群名，不按名称合并。平台标签在选中、搜索、暂停同步后始终保留。
- QQ 使用企鹅图标和蓝色标签；企微使用工作图标和绿色标签。文字是主要依据，颜色和图标辅助辨识，避免仅靠色差传递含义。
- 平台数量变多后，保留常用来源并收进“更多来源”；本版只验证当前 QQ 与企微场景。
- 账号备注与平台分开；多账号时使用真实数据源名称或用户备注。缺少账号信息就省略账号，不推断“个人／工作”。原型中这两个名称仅为示例。

## 落地依据

- `src/types/base.ts` 的 `AnalysisSession.platform` 已有平台字段。QQ 适配器返回 `qq`，企微适配器返回 `wecom`。首期来源标签和筛选可直接使用该字段，不需要重新导入历史或改群名。
- 增加统一平台展示映射供侧栏和标题共用；`wecom` 展示“企业微信”，与个人微信 `wechat` 分开。未知值显示“来源未知”，不从会话名称猜平台。
- 平台是聊天发生的地方，导入方式是文件或自动同步；二者独立。文件导入的 QQ 会话也显示 QQ，导入方式另在详情展示。
- 数据源详情通过 `DataSource.sessions[].targetSessionId` 关联 ChatLab 会话后读取。查不到映射时展示已有信息并省略同步字段；不按平台把多个账号的数据源随意归到一起。
- 标题和列表展示共用会话字段。未知来源或映射缺失时均显示明确回退文案，不虚构账号、导入时间或连接状态。
- 侧栏当前虚拟列表行高为 44px。正式实现需让两行信息与虚拟滚动的测量一致，并确认长群名省略后平台标签仍完整显示。
- 当前设计未改生产页面、数据库和后台采集配置；原型不用作正式组件直接发布。

## 运行与验证

仓库根目录执行：

```bash
python3 -m http.server 4318 --bind 127.0.0.1
```

打开 `http://127.0.0.1:4318/src/components/common/sidebar/SourceIdentity.prototype.html`。也可直接打开 HTML 文件，资源全部内嵌，状态仅保存在内存。

已在浏览器验证：企微筛选、来源与私聊组合、跨平台同名群搜索及切换、来源详情、无结果清空筛选、浅深色切换。使用示例消息；账号备注和同步时间均为示例。浏览器控制台无错误。
